# 个人门户自身许可证与合规盘点运行方式

## 部署前检查

每次部署会在 npm 安装后运行严格许可证预检：检查个人门户生产依赖的许可证元数据、本地许可证文件及第三方声明文件中的包/版本章节。发现缺项时，部署在切换线上版本前终止。预检报告写入部署临时目录，不会污染 Git 工作区。

## 完整盘点

运行方式：

    sudo /opt/personal-portal/scripts/compliance/run-audit.sh

该脚本只扫描个人门户自身源代码、公开静态文件、当前发布目录、第三方依赖闭包及许可证声明，并将门户自身资产、许可证候选、证据和扫描任务写入版权合规专有表。它不读取或扫描用户文章、教育资源、上传图片或外部链接。报告存储在 `/var/db/personal-portal/compliance-reports`，目录权限限制为 root。

完整盘点只会新增/更新门户自身的许可证台账、保留历史哈希并将已不存在的门户自身旧版本标记为非活动；不会修改用户内容或教育资源。

## 定期执行

建议每日执行完整盘点，并在每次部署时执行严格许可证预检。定期任务使用独立报告目录，不修改 Git 工作区。自动识别的高风险项仍需要人工核对许可证及分发义务，不能由扫描器自动作出法律结论。

## 公共版权投诉入口

外部用户内容的公开版权投诉表单、管理界面和 API 已移除。公开版权通知和投诉文档不再对外提供；第三方软件许可证声明仅作为门户开发依赖合规材料保留在内部台账。

## 数据保留审计（只读 / Dry-run）

每日盘点同时生成 `retention-dry-run.json`、`upload-filesystem-inventory.txt` 与 `backup-retention-inventory.txt`。报告统计过期会话、软删除内容/资源、上传文件与登记记录的数量差异。报告目录仅 root 可读。

此阶段只生成报告，不执行删除。文章/资源回收站、未登记上传文件和备份的保留期仍需明确。

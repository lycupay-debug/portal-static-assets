# 版权资产盘点运行方式

## 部署前检查

每次部署会在 npm 安装后运行严格许可证预检：检查生产依赖许可证元数据、本地许可证文件及第三方声明文件中的包/版本章节。发现缺项时，部署在切换线上版本前终止。预检报告写入部署临时目录，不会污染 Git 工作区。

## 完整盘点

运行方式：

    sudo /opt/personal-portal/scripts/compliance/run-audit.sh

该脚本读取当前数据库文章和教育资源、生产发布目录、上传文件、教育资源存储目录、前端依赖和第三方声明文件，生成 CSV/JSON/Markdown 报告，并将资产、许可证候选、证据、扫描任务和高风险待审记录写入版权合规专有表。报告存储在 /var/db/personal-portal/compliance-reports，目录权限限制为 root。

完整盘点只会新增/更新台账、保留历史哈希并将已不存在的旧版本标记为非活动；不会自动删除用户内容、公开文章、教育资源或第三方依赖。

## 定期执行

建议每日执行完整盘点，并在每次部署时执行严格许可证预检。定期任务使用独立报告目录，不修改 Git 工作区。任何自动识别的高风险项仍需要人工核对授权链，不能由扫描器自动作出侵权结论。

## 投诉入口安全门槛

版权投诉表单只有在“版权投诉”和“隐私政策”均正式发布后才可接收信息。此外，服务必须设置 PERSONAL_PORTAL_COMPLAINT_RETENTION_DAYS（30–3650 天），并与经审核发布的隐私政策保持一致。未配置时，接口保持关闭。具体保留期限需根据实际业务和法律需求确定，不由程序擅自决定。

## 数据保留审计（只读 / Dry-run）

每日完整盘点同时生成 `retention-dry-run.json`、`upload-filesystem-inventory.txt` 与 `backup-retention-inventory.txt`。报告统计过期会话、软删除内容/资源、投诉保留期限到期或缺失，以及上传文件与登记记录的数量差异。报告目录仅 root 可读。

此阶段只生成报告，不执行删除。过期会话可按现有会话有效期规则评估清理；文章/资源回收站、投诉证据、未登记上传文件和备份的保留期仍需明确。投诉数据在保留期限、法律保全（legal hold）规则和执行机制获批前不得自动清理。当前数据库尚未实现法律保全字段/流程，因此不能将“无保全”视为已确认。

## 上传图片版权门禁

- 新上传的 PNG/JPEG/GIF/WebP/AVIF 图片会写入独立图片登记表和版权资产台账，记录上传者、文件哈希、MIME 类型和大小；初始权利状态为未知、审核状态为待审核。
- Caddy 不再直接公开静态上传目录；`/uploads/<filename>` 请求会转发给 API 进行授权检查。待审核图片仅允许上传者或管理员预览。
- 图片只有在版权资产审核、权利依据和已核验证据满足发布门槛，且被至少一篇当前公开文章引用时，才允许匿名公开访问。文章发布门禁会逐一检查正文引用的站内上传图片。
- 旧上传文件不会自动删除。未在新图片登记表中登记的旧路径会返回 404，需在确认权属和是否仍需使用后再决定登记、迁移或删除。

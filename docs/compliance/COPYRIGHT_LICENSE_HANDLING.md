# 版权与第三方许可证处理规程

状态：开发阶段执行规程
适用范围：个人门户及其前端/后端依赖、静态资源、字体、图标、图片、文档、代码片段和其他外部素材。
原则：先确认来源与实际使用，再核对许可证原文和分发方式，最后补齐声明、保存证据并验证产物。自动扫描结果不等于法律审查结论。

## 1. 每次发现版权或许可证问题时的固定流程

1. **定位实际资产**：记录准确名称、版本、文件路径、直接/间接依赖关系、是否进入生产构建产物、是否由服务器发给用户，以及是否修改过。
2. **收集一手证据**：优先查看对应版本上游仓库/发行包内的 LICENSE、LICENSE-*、COPYING、NOTICE、源文件头和官方项目说明。包管理器的 license 字段仅作为索引，不代替许可证原文。
3. **确认授权选项**：对 A OR B 这类多重授权，逐一核对原文，并在本项目记录明确选择的选项；不能把 OR 误读成必须同时满足所有许可证，也不能在没有证据时自行选取。
4. **按实际分发方式判断义务**：区分仅在服务器内部运行、通过网页向浏览器发送 JavaScript/CSS/字体/图片、分发二进制、分发源码、修改上游文件等情况。不要只因“是网站”就认为没有分发；浏览器收到的客户端文件通常属于对外提供软件副本的情形。
5. **补齐声明材料**：按所选许可证保留其要求的版权声明、许可文本、NOTICE/专利声明（如适用），以及必要的源码获取方式/修改文件告知。第三方许可证不能被项目自有许可证覆盖或改写。
6. **保存可复核证据**：记录上游 URL、版本/标签、锁文件版本与 integrity、许可证文件路径和 SHA-256、检查日期、所选许可证、分发形态、修改状态、需履行的义务、核验人/状态。
7. **更新并验证交付物**：更新源码仓库中的第三方声明和合规记录；重新生成/构建后检查 frontend/public/THIRD_PARTY_NOTICES.txt、frontend/dist/THIRD_PARTY_NOTICES.txt 与实际发布目录中的声明一致。运行许可证资产扫描和相关测试；任何未解决项保持 pending/unverified，不得标记为已批准。
8. **记录到本 Notion 页面**：每个新问题新增一条案例记录，注明采用的许可证类别、证据、决策、修复、验证结果和复查触发条件。以后同类问题沿用已验证流程；不同许可证/素材类型必须先查找对应许可证原文和权威指导，不可机械套用本案例。

## 2. 多重授权（例如 MPL-2.0 OR Apache-2.0）的专用方法

- 从实际安装版本中分别检查所有许可证文件；例如 LICENSE 与 LICENSE-MPL 可能对应不同授权选项。
- 阅读上游的明确授权语句，确认是 OR（任选其一）还是 AND（需同时满足），并保留原始表述。
- 根据项目实际交付方式选择一项最适合、且确实由上游提供的授权。记录选择理由；不要将依赖改称为“完全属于本项目”或声称依赖在所有情况下均无义务。
- 如果选择 Apache-2.0，核对并保留完整 Apache 2.0 许可证文本及上游随附的版权/归属声明；检查 NOTICE（若上游提供或许可证要求）。
- 如果选择 MPL-2.0，必须单独评估 MPL 的文件级 copyleft、修改文件的许可和源码提供义务；在向外分发修改后的 MPL 覆盖源码/可执行形式时，依 MPL 2.0 第 3 节核验相应义务。
- 即使选择了其中一项，也保留可用授权选项和选择记录，避免误以为另一份许可证文本就是项目自身的许可证。
- 若上游没有提供清晰授权、许可证文件与元数据冲突、来源/版本无法确定，或分发方式存在重大不确定性，保持阻断/待人工复核状态，不自行推定授权。

## 3. 其他类型应分别适用的处理方法

- **MIT/BSD/ISC 等宽松许可证**：核对准确版权声明和完整许可文本是否随副本/实质部分保留。
- **Apache-2.0**：除许可证文本外，核对已有版权、专利、NOTICE 等声明；修改文件应按许可证要求标明修改。
- **MPL/LGPL/GPL/AGPL 等 copyleft 许可证**：必须根据许可证的具体触发条件、修改情况、链接/组合方式和分发/网络提供方式做专项审查；不能只补一个版权页就结案。
- **字体、图标、图片、视频、音频、文档及网页素材**：核对素材本身的授权，而不是只核对下载网站；记录作者/权利人、原始来源、许可证、署名格式、商业使用/修改/再分发限制、版本或文件哈希。
- **商业、专有、非商业、评估版、Sustainable Use 或自定义许可证**：在核对合同、用途、受众和再分发权限前，不视为可自由商业使用；重大不确定性应暂停纳入或发布并报告。
- **没有许可证/来源不明/授权链不清**：默认待核实，不等于公有领域或允许使用；优先取得明确授权或替换为来源可靠且许可兼容的资产。
- **用户上传内容**：与项目依赖分开管理；不得将项目依赖的许可证结论套用到用户文章、图片或外链内容。

**证据**：
- 锁文件：frontend/package-lock.json 的 node_modules/dompurify 条目，版本 3.4.17，包含 integrity 值。
- 安装包文件：frontend/node_modules/dompurify/LICENSE（Apache 2.0）和 LICENSE-MPL（MPL 2.0）。
- 上游项目/版本：https://github.com/cure53/DOMPurify/tree/3.4.17
- 上游分发 bundle 头部原文：(c) Cure53 and other contributors，并指向对应版本的 LICENSE。

# 内容与文件生命周期约定

更新时间：2026-10-31

## 文章与内嵌图片

- 将文章移入回收站只设置 `deleted_at`，不得删除正文、图片登记或图片文件，以支持恢复。
- 永久删除仅允许操作当前用户回收站中的文章。
- 内容创建、更新和历史版本恢复，在写入前对正文涉及的托管图片文件名排序并获取 PostgreSQL transaction advisory lock；新正文只能引用 `portal.uploaded_images` 中已登记的图片。
- 永久删除先对目标正文中的托管图片加同一事务锁，再删除文章并检查剩余当前正文及所有可恢复历史版本快照。只要任一当前正文或历史快照仍引用图片，就保留登记和文件。
- 无剩余引用时，在删除事务内移除 `portal.uploaded_images` 登记并写入 `portal.event_inbox` 清理事件；事务提交后由 Go 事件处理器删除文件。清理操作对文件不存在的情况幂等，PostgreSQL outbox/lease/retry 是恢复依据。
- 图片访问先检查数据库登记，再判断当前已发布公开内容是否引用；否则仅上传者或管理员可访问。Caddy 不得直接静态暴露上传目录；图片必须经 Go 权限检查路径。

## 图片上传

- 上传前验证认证会话、MIME 白名单、文件签名和 8 MiB 大小上限；文件使用安全 UUIDv4 命名，并通过 `os.Root` 在托管目录内以独占创建方式写入。
- 文件登记使用显式 PostgreSQL 事务。事务开始或 INSERT 明确失败时回滚并移除新文件。
- COMMIT 返回错误时，提交结果可能不确定；不得直接删除文件，以免数据库实际提交后产生指向缺失文件的登记。接口返回 503 并保留文件，供后续核验。

## 教育资源

- 移入回收站仅软删除资源记录，保留资源文件供恢复。
- 新建资源先写入托管文件，再在显式数据库事务中创建资源记录。事务开始或 INSERT 明确失败时回滚并移除新文件；COMMIT 结果不确定时保留文件并返回 503。
- 更新资源先锁定资源行，再写入替换文件；数据库更新和旧文件清理 outbox 事件在同一事务提交。相同文件内容不重复写入；提交结果不确定时保留新文件。
- 永久删除仅针对当前用户回收站中的资源；删除记录与清理 outbox 事件在同一事务提交，随后由事件处理器删除文件。
- 资源文件当前按单条资源记录归属，不支持跨资源共享；若未来引入共享，必须先设计显式引用关系。

## 文件系统与数据库一致性边界

PostgreSQL 事务与文件系统不能形成原子提交。明确失败时可以回滚数据库并删除新文件；提交结果不确定时优先保留文件，避免产生已提交记录指向不存在文件的损坏状态。若事务最终回滚，保留文件可能成为孤儿文件；当前没有自动扫描并回收此类孤儿文件的定期任务，需通过后续文件完整性核验/恢复流程处理。此取舍优先保护可恢复业务数据，不以猜测提交结果为依据删除文件。

## 自动化验证

- `content_image_cleanup_integration_test.go`：历史版本图片引用保留、并发新增引用与永久删除的两种锁顺序。
- `resource_concurrency_integration_test.go`：缺失文件修复、并发替换串行化和 outbox 清理。
- `managed_file_transaction_test.go`：图片上传/资源新建在 INSERT 明确失败时清理文件；COMMIT 结果不确定时保留文件。
- `managed_files_test.go`：路径穿越、符号链接逃逸、独占写入和文件签名校验。
